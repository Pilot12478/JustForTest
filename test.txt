origin/master - локальная копия удаленного мастера
master - ваша локальная ветка

Git это программа которая позволяет создавать версии проекта и переключаться между ними
Для того чтобы гит начал следить за проектом нужно перейти в папку с проектом с помощью команды
cd пусть до папки
 git init внутри директории создастся папка .git, это и будет локальным репозиторием, где будет хранятся все коммиты
(создаем хранилище коммитов, гит клон, гит пуш заполняем это хранилище коммитами)
 git add . или git add имя файла (мы говорим гиту, что хотим чтобы он следил за изменениями в этих конкретных файлах)
 git commit -m " название коммита" и вот теперь мы уже сохраняем коммит в локальный репозиторий
 git log смотрим историю где показана дата, автор и хэш коммита
 git status показывает на какой ветке мы находимся, за какими файлами следит гит и есть ли какие-то незакомиченные изменения
 git fetch origin master - «сходи в origin, скачай коммиты ветки master, обнови локальную ссылку origin/master, ничего не трогай».
 git rebase origin/master - Возьми мою текущую ветку и переставь её коммиты поверх кончика origin/master
 git pull origin master -  «сходи в origin, скачай коммиты ветки master, и сразу смержи их в мою текущую ветку».

чтобы например переключиться на какой-то более старый коммит можно выполнить команду git checkout + хэш коммита(семь первых символов)


чтобы создать новую ветку и работать в ней нужно выполнить команду git branch + название ветки без пробелов (new-branch)
чтобы посмотреть список всех веток то просто выполняем команду git branch



стандартный флоу работы над задачей
стягиваем последние изменения из удаленного репозитория себе в локальный репозиторий командой git pull
создаем отельную ветку для работы надо задачей командой git branch + название ветки
переключаемся на отдельную ветку с помощью команды git checkout + название ветки
завершаем задачку делаем коммит с помощью команды git add + название файла, далее жмакаем git commit -m + название коммита

опционально если мастер ушел вперед
git fetch origin 
git status (смотрим ушел ли мастер вперед, есть ли новые коммиты)
git rebase origin/master (берем нашу текущую ветку и переставляем ее коммиты поверх кончика мастера)

далее ветка пушится на удаленный репозиторий командой git push

создать пул риквест в удаленном репозитории и отправить на ревью чтобы влить в мастер

далее уже кнопкой  "Merge pull request" наша ветка с задачкой сливается в мастер

Три способа мержа PR
1. Merge commit (обычный «Create a merge commit»)
Да, создаёт новый коммит в master — merge-коммит.

text
master:      A --- B --------------- M   ← новый коммит M
                  \                 /
feature:           C --- D --- E ---
M — новый коммит с двумя родителями (B и E).

Все коммиты ветки (C, D, E) тоже становятся частью истории master.

История ветвится, но всё видно.

2. Squash and merge
Да, создаёт новый коммит — но один, вместо всех коммитов ветки.

text
master:      A --- B --- S   ← один новый коммит S
                  \
feature:           C --- D --- E   (в историю master не попадают)
S — новый коммит, в который «сжаты» все изменения из C, D, E.

Исходные коммиты ветки в master не попадают.

История линейная.

3. Rebase and merge
Формально новых коммитов в смысле «одного добавленного» нет — коммиты ветки пересоздаются поверх master и добавляются как есть.

text
master:      A --- B --- C' --- D' --- E'
C', D', E' — это те же изменения, что в C, D, E, но с новыми хешами (пересозданы поверх B).

Merge-коммита нет.

История линейная.

С точки зрения «сколько новых коммитов появилось в master» — появилось три (по числу коммитов в ветке), а не один.



разговор по ветвлению
 A --- B ---С - допустим это origin master
мы сделали git push и обновили наш локальный мастер облачным мастером
теперь у нас тоже  A --- B ---С
мы создали ветку из точки С и добавили два новых коммита git commit -m
C--F--D - наша ветка созданная на базе С (самого свежего мастера на тот момент)
потом сделали git fetch и например поняли что мастер ушел вперед командой git status
текущий мастер A--B--C--M
мы находясь в нашей созданной ветке делаем после чего git rebase origin/master
после чего наша ветка с ее коммитами пересобирается теперь на новой базе
таким образом получаем
M--F--D
